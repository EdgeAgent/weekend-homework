# Community Build Guide

Weekend Homework is designed as a public build-along, not a static download.

## Build weekends

A build weekend has four phases:

1. **Pick** — choose one of the five projects and announce your fork or repo.
2. **Build** — follow the guide in small steps and post progress, blockers and screenshots.
3. **Verify** — run the checklist in the project folder. Do not skip the definition of done.
4. **Show** — add a showcase submission with a demo link and a short explanation of your version.

## What belongs in a progress post

- Project number and name
- What is working now
- One screenshot or short clip
- The current blocker, if any
- The next step

## Ways to contribute

- Submit a finished build to the showcase.
- Improve a guide with a clearer step or a real pitfall you hit.
- Add an alternative stack version (for example, a local-only second brain).
- Translate a guide.
- Review another builder's submission for broken links, exposed secrets or missing screenshots.

## Showcase review

Maintainers check that:

- the project and repository links resolve;
- at least one real screenshot or demo is present;
- the submission identifies the builder and project correctly;
- no credentials or private documents are exposed;
- the entry does not claim features that are not demonstrated.

Approval means the showcase record is complete. It is not a security audit or an endorsement of the submitted code.

## Featured builds

A build can be featured when it is working, clearly documented, and teaches the community something new: a better interface, a local-only approach, a useful integration, or a version adapted for a real client or business.
